================================================================================
1. EXECUTIVE SUMMARY & CORE MISSION
================================================================================
Relay Capture (relaycapture.com) is an enterprise-grade email deliverability and DNS infrastructure engineering web application. Its primary mission is to diagnose, explain, and remediate email authentication failures (SPF, DKIM, DMARC, BIMI) that cause outbound B2B emails to be quarantined or rejected by major mailbox providers (Google Workspace, Microsoft 365, Yahoo Mail, Apple Mail).

The application positions deliverability not as a generic marketing trick, but as an enforceable cryptographic standard. It combines an authentic, client-side public DNS-over-HTTPS scanner with an interactive pipeline risk scenario calculator, real-time provider compliance feeds, and a zero-friction, one-time flat-fee checkout system.


================================================================================
2. HIGH-LEVEL TECHNICAL ARCHITECTURE & STACK
================================================================================
- Framework: Next.js 15 (App Router with React 19 and React DOM 19)
- Language: TypeScript 5 (Strict mode)
- Styling: Tailwind CSS 3.4 with custom CSS extensions and Vanilla CSS variables
- Iconography: Lucide React (feather-style clean SVG icon library)
- Motion & Animation: Framer Motion (v12) for layout transitions, custom requestAnimationFrame loops, and Canvas API animations
- Graphics & WebGL: Three.js and custom GLSL fragment shaders (Silk ribbon simulation, particulate fields)
- External DNS Engine: Cloudflare Public DNS-over-HTTPS JSON API (https://cloudflare-dns.com/dns-query)
- Payment Gateway: Paddle Billing v2 SDK (cdn.paddle.com/paddle/v2/paddle.js) with client token and price ID binding
- Hosting & Deployment: Vercel edge deployment with fully pre-rendered static export (9/9 static routes)

4. PAGE FLOW & ROUTING ARCHITECTURE
================================================================================
The application employs a hybrid architecture:
1. Multi-Route Static Pages for SEO & Direct Deep Linking:
   - / (Home / Landing view)
   - /pricing (Dedicated Commercial Engagement & Full Capabilities Matrix)
   - /terms (Terms of Service)
   - /privacy (Privacy Policy)
   - /refund (14-Day Money-Back Guarantee & Refund Policy)
   - /opengraph-image (Automated Dynamic Social Preview Image)

2. In-Memory SPA View Switcher (src/App.tsx):
   Within the root Next.js client component (src/App.tsx), a central state 'currentView' manages instant, zero-reload navigation between:
   - 'landing' (Default complete landing page)
   - 'pricing' (Full-page pricing view with comparison matrix and FAQ)
   - 'terms', 'privacy', 'refund' (Standalone legal viewports)
   This allows seamless transitions with teleport overlay animations and instant response times, while browser history and direct URLs are simultaneously supported via Next.js router integration.

- Functional Mechanics:
  * Cleans input string (strips http://, https://, www., paths).
  * Asynchronously queries Cloudflare DoH (https://cloudflare-dns.com/dns-query) for:
    1. Root TXT records (SPF verification)
    2. _dmarc.{domain} TXT records (DMARC policy inspection)
    3. Dictionary sweep of 10 standard DKIM selectors ({selector}._domainkey.{domain})
  * Computes mathematical health score:
    - SPF: Pass (-all) = 40 pts, Warn (~all) = 20 pts, Fail/Missing = 0 pts.
    - DMARC: Pass (p=reject / p=quarantine) = 45 pts, Warn (p=none) = 20 pts, Missing = 0 pts.
    - DKIM: Pass = 15 pts.
  * Computes letter grade (A+, A, B, C, D, F) and spoofing exposure risk level.
  * Dispatches computed ScanResult to parent application state to synchronize the Financial Leakage HUD.

    - Left Panel (Interactive Risk Decay Canvas):
      * Attached top tab displaying live domain favicon, domain name, last scan timestamp, and severity badge ("Healthy", "Uh oh...", "Blacklisted").
      * 12-Month Polyline Graph rendering dynamic SVG decay curves with fill area gradient.
      * Interactive hover crosshair calculating monthly loss for each specific month node.
      * Bottom 2-Metric KPI Ribbon:
        1. "Estimated Pipeline Impact" (e.g. $88,200/yr (Scenario Model))
        2. "Est. Undelivered Messages" (e.g. ~3,500 emails/mo)
    - Right Panel (4 Interactive Parameter Controls):
      * Box 1: Monthly Outbound Volume (Range slider: 1,000 to 100,000 sends)
      * Box 2: Estimated Spam / Quarantine Rate (Range slider: 1% to 65% based on scan score)
      * Box 3: Average Value per Deal (Range slider: $100 to $50,000+)
      * Box 4: Assumed Reply-to-Deal Rate (Range slider: 0.05% to 0.50%, default 0.15%)
    - Bottom Sensitivity Footnote:
      "* Scenario sensitivity model based on user-adjustable conversion & volume assumptions to illustrate potential pipeline impact when deliverability degrades."

- Functional Mechanics:
  * Formula:
    1. Quarantined Messages = Outbound Volume × (Spam Rate / 100)
    2. Monthly Pipeline Loss = Quarantined Messages × (Assumed Deal Rate / 100) × Deal Value
    3. Annual Pipeline Impact = Monthly Pipeline Loss × 12
  * Mathematical Normalization:
    The 12-node curve distributes the annualized loss across 12 compounding decay weights such that Sum(Month 1 .. Month 12) exactly equals the computed annual pipeline impact to the dollar.
  * Real-Time Synchronization:
    When a scan completes in the Domain Checker, the computed quarantine risk percentage automatically initializes the slider in Box 2.

6.1 CLOUDFLARE DNS-OVER-HTTPS (DoH) DIAGNOSTIC ENGINE
--------------------------------------------------------------------------------
- Endpoint: https://cloudflare-dns.com/dns-query
- Request Method: GET with Header { 'Accept': 'application/dns-json' }
- Execution Pipeline:
  1. queryDnsTxt(domain): Queries TXT records (type 16).
  2. Parses Answer array, stripping quote delimiters.
  3. Identifies SPF mechanism (v=spf1), scans for -all, ~all, ?all, +all, and counts includes.
  4. Queries _dmarc.{domain}, scans for v=dmarc1, p=reject, p=quarantine, p=none.
  5. Concurrently executes Promise.all across 10 common DKIM selector prefixes ({selector}._domainkey.{domain}).
  6. Returns structured ScanResult object containing timestamp, grade, composite score, raw values, plain-English explanations, and remediation blueprints.

--------------------------------------------------------------------------------
6.2 PADDLE V2 DIRECT OVERLAY CHECKOUT (src/utils/paddle.ts)
--------------------------------------------------------------------------------
- Script Injection: Dynamically injects https://cdn.paddle.com/paddle/v2/paddle.js into document head.
- Configuration:
  * clientToken: process.env.NEXT_PUBLIC_PADDLE_CLIENT_TOKEN || 'YOUR_PADDLE_KEY_HERE'
  * environment: 'production' (or sandbox)
  * price IDs:
    - Self-Serve Blueprint ($247): NEXT_PUBLIC_PADDLE_PRICE_SELF_SERVE || 'YOUR_PADDLE_KEY_HERE'
    - Turnkey Remediation ($547): NEXT_PUBLIC_PADDLE_PRICE_TURNKEY || 'YOUR_PADDLE_KEY_HERE'
    - Managed Outbound ($1,247): NEXT_PUBLIC_PADDLE_PRICE_MANAGED || 'YOUR_PADDLE_KEY_HERE'
- Execution:
  Calling openPaddleCheckout(priceId, planName) initializes Paddle.Initialize and triggers Paddle.Checkout.open({ items: [{ priceId, quantity: 1 }] }), providing an in-page modal checkout without external redirects.
